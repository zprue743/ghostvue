# GhostInlineAlert

`GhostInlineAlert` is inline contextual feedback for errors, warnings, and
recoverable failures near the content they describe. Import it from
`@ghostvue/vue` for headless use, or from `@ghostvue/themes` for the default
visual treatment.

<GhostExample id="inline-alert/billing-notices" />

The billing status card stacks `solid`, `soft`, and `outline` `GhostInlineAlert`
variants with contextual `GhostButton` actions and a polite status region.

## Basic use

<GhostExample id="inline-alert/basic" />

The root is a native `div` by default. Use `as="section"` when the alert is a
named landmark with a title. Static copy uses `announce="off"` (the default) so
assistive technology reads it in document order without a live-region
announcement.

<GhostExample id="inline-alert/composable" />

## Live regions

Set `announce` to `status` or `alert` only when copy **appears or changes after
mount** — for example after a failed save or a delayed load error. Do not use
live semantics for copy that is present in the initial HTML with no later
change unless you intentionally want a mount announcement.

| `announce` | Role on root | Typical use                                       |
| ---------- | ------------ | ------------------------------------------------- |
| `off`      | (none)       | Static contextual feedback present on first paint |
| `status`   | `status`     | Recoverable or informational updates              |
| `alert`    | `alert`      | Urgent errors needing immediate attention         |

| Slot      | Slot props | Description                                                            |
| --------- | ---------- | ---------------------------------------------------------------------- |
| `actions` | —          | Optional action controls such as GhostButton. Children stay focusable. |
| `message` | —          | Primary supporting copy.                                               |
| `title`   | —          | Optional heading. Rendered as h1–h6 from headingLevel.                 |

<!-- @generated docs-api:vue/ghost-inline-alert end -->

Slots: `#title`, `#message`, `#actions`. Native attributes fall through to the
root. A template ref exposes `element: HTMLElement | null`.

When `#title` is present, `as` is `section`, and `announce` is `off`, the root
receives `aria-labelledby` pointing at the heading id generated by
`useGhostId`.

`@ghostvue/themes` adds these to the headless `GhostInlineAlert` API, which it forwards:

| Prop      | Type                                        | Default     | Description                                         |
| --------- | ------------------------------------------- | ----------- | --------------------------------------------------- |
| `variant` | `'solid' \| 'soft' \| 'outline' \| 'ghost'` | `"soft"`    | Visual treatment. The default omits data-variant.   |
| `tone`    | `'accent' \| 'neutral' \| 'danger'`         | `"neutral"` | Semantic color intent. The default omits data-tone. |

<!-- @generated docs-api:themes/ghost-inline-alert end -->

Behavioral props (`announce`, `headingLevel`, `as`) pass through to the unstyled
component. Defaults omit `data-variant` and `data-tone` so CSS treats missing
hooks as `soft` / `neutral`.

## Table and mutation failures

Use above or inside a table region for load and mutation failures. Keep actions
in `#actions` so retry controls stay keyboard reachable.

## When not to use it

- **Global or transient feedback.** Use [`GhostToast`](./toast.md) with
  `GhostToastProvider` and `useGhostToast`.
- **Field validation errors.** Use `GhostFieldError` inside `GhostField`.
- **Always-on page chrome with `announce="alert"`.** That spuriously announces
  on every visit. Keep `announce="off"` for static copy.

## Styling

The unstyled root uses class `ghost-inline-alert`, `data-part="root"`, and
`data-ghost-inline-alert`. Slot wrappers use `data-part="title"`, `message`, and
`actions`. There is no `data-state` hook.

## Accessibility

- Prefer `announce="off"` for copy present on first paint.
- Use `announce="alert"` when an error appears after an async action.
- Use `announce="status"` for recoverable informational updates after load.
- Interactive controls belong in `#actions`; the root is not focusable.
